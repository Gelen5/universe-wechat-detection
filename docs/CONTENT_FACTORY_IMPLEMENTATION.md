# 爆款成品库：实现与验收记录

## 功能与交易

- 管理员从现有低粉榜快照选择来源，建立文章或图片草稿；文章可手动提交后台模型任务，图片通过管理员上传；管理员确认事实、素材权利和内容后上架。
- 用户以服务端价格独家买断，商品行的条件更新串行化竞争；钱包分桶、积分账本和买家归属在同一事务中提交。重复购买由原买家得到成功结果，其他买家不能再次购买。已售内容不允许编辑或下架。
- 正文和原图只经已购权限接口返回，原图以数据库二进制保存，不放公共静态目录；买家可提交文字反馈。没有定时生成任务。
- 文章生成调用公众号 Plus 的模型配置及 JSON 生成接口，载入 Skill 的写作与质量规范，但不等同于运行完整公众号 Skill 的研究、写作和审核流程。任务结果必须人工审核。

## 本地运行和迁移

安装 `requirements.txt` 并配置现有数据库、Redis、Celery 和文字模型。对新建或已验证迁移历史的测试库执行 `alembic upgrade head`；然后按项目现有方式启动 Web、Redis 和监听 `chat` 队列的 Celery worker，访问 `/content-factory`。缺少新表时接口返回 503，不阻断原有功能。

生产环境 Alembic 版本落后于实际表结构，禁止直接升级。先备份，再执行 `python -m scripts.install_content_factory_schema`，只创建成品库新表并验证列及唯一约束。正常 Alembic 路径保留 `20261107_0017` 以支持干净数据库。不要在有购买记录后删表回滚，回退代码应保留成品及账本数据。

## 已知限制与未完成验证

- 在隔离的 PostgreSQL 临时数据库验证了 20 用户并发争购、重复请求、余额不足与账本写入异常回滚；生产迁移仍需先完成备份和专表创建。
- 已只读核实生产低粉榜存在来源快照，管理员须逐条核验链接后审核上架。
- 本地使用模拟 API 的商品数据检查了桌面及手机商品详情；已用真实模型配置完成一次生成调用；尚未在真实 Redis worker 上运行成品库任务，也尚未进行真实用户扣分购买的浏览器端到端验收。
- 手动生成任务具备租约与定时恢复，过期 worker 不能覆盖新任务结果；Redis/Celery 真实中断恢复尚未联调。平台应人工审核，无法自动证明事实或版权。
- 图片提供低分辨率模糊预览；原图保存在数据库中，容量和备份成本需要根据商品规模评估。

## 本次测试

- 成品库相关测试：13 项通过，包含 SQLite 并发、异常回滚、图片和文章授权、真实应用的登录与购买链路、模拟模型生成、过期任务防覆盖以及新表迁移创建。
- 账户与计费回归：21 项通过、2 项失败。失败测试引用不存在的 `WORKBENCH_EXECUTOR`；在未包含本功能的既有分支上复测仍失败，不能算本次通过。
- 桌面 1280×800 与手机 390×844 浏览器页面使用模拟 API 验证详情可打开、无横向溢出。不是实际线上购买测试。
