# 全赛道文章质量优化：实施与验收

目标：让不同题材按照读者任务、材料和文体组织内容，减少空泛重复，并保留现有一键生成路径。

## 实施顺序

1. 一键成文增加可选的文章目标、内容形式和素材提示；默认自动判断，空值可直接生成。旧稿和旧客户端继续可用。
2. 两条公众号写作链路共享编辑原则：按内容自主选择推进路径，现实与虚构边界分别处理；用户明确要求优先，不编造现实经历、证据或结果。
3. 继续沿用已存在的去 AI 局部复核、前后对照与恢复；本批不增加模型调用、收费步骤或阻塞式追问。
4. 以客户授权的真实选题建立跨赛道质量样本，记录原材料、改稿时间、可发布性与修改原因；由人工复核，不能将提示词命中当成真实质量提升。
5. 根据试用反馈迭代具体赛道、复核提示和界面。对材料不足的提醒采用可跳过形式，只有需要用户自有经历时才建议补充，不阻止生成。

跨赛道合成测试方向和真实用户反馈记录见 `writing-quality-evaluation.md`。

## 验收与回滚

- 新选项全为空时，原入口、流式生成、保存与历史恢复、积分扣退、失败保留原稿均可用；旧客户端更新草稿时不擦除新增字段。
- 实测自动模式及教程、观点、故事等代表性文体，确保明确虚构与现实事实采用不同边界；未覆盖的赛道可通过自动判断或自由补充要求使用。
- 质量评价包括文章信息增量、依据、结构适配和实际修改量；不得保证检测器分数、生成质量或所有赛道效果。
- 回滚代码到上一完整版本；新增草稿字段为 JSON 可选字段，无数据库结构迁移、不重算积分。回滚期间旧版更新可能丢失新字段，需先备份受影响草稿。

## 第一批验证记录（2026-10-27）

- 模拟生成覆盖空选项、已填写选项、旧客户端保存、历史恢复、流式完成、扣分与失败退款；真实前端浏览器验证空选项和填写选项两条路径均可生成。
- 全项目回归在最后一处虚构文体提示措辞调整前为 632 passed、37 subtests passed；调整后对写作节点、两条创作链路及浏览器流程补跑 55 passed。不是用例数相加。
- 通过配置的真实模型，以三份不含客户隐私的合成素材分别生成职场教程、明确虚构故事和美食教程；输出和时间保存在仓库外 `workbench-audit-20261027/writing-quality-live-probe.txt`。未进行优化前后对照，也未覆盖全部赛道。
- 三篇能完成流式生成，文体有区别；虚构故事仍出现套路化结尾。该结果只能证明所测场景可调用模型，不能证明文章质量提升或真实客户满意。
- 真实受邀用户的文章、修改时长、满意度与各赛道表现待获得授权并收集后评测。主流程不引入新收费节点；无需填写新增选项即可继续生成。
