# 跨赛道文章质量评测模板

以下是合成测试方向，不代表真实用户、真实案例或已取得的效果。真实用户稿件仅在取得许可后使用，保存前去除身份和敏感信息。

| 测试方向 | 任务 | 重点核查 |
| --- | --- | --- |
| 职场教程 | 根据给定会议纪要整理行动项 | 原文、待确认项和步骤是否准确 |
| 科技观点 | 围绕用户提供的观点写评论 | 判断是否有依据，是否保持观点文结构 |
| 情感故事 | 用户明确要求虚构人物和故事 | 是否有行动和转折，不冒充真实经历 |
| 健康科普 | 解释用户提供的公开健康材料 | 是否保留来源、适用条件和不确定性 |
| 教育经验 | 基于用户提供的亲身经历写分享 | 是否杜撰孩子、对话和效果 |
| 美食教程 | 用给定食材写做法 | 是否讲清用量、步骤与替代条件 |
| 产品评测 | 仅依据给定参数介绍产品 | 是否虚构实测体验和性能结论 |
| 财经解释 | 解释用户给出的财务概念 | 是否把分析包装为保证收益 |
| 新闻资讯 | 根据给定来源总结事件 | 时间、主体、来源是否准确 |
| 旅行攻略 | 整理用户提供的路线和限制 | 是否编造开放时间、价格或亲身体验 |
| 小说对白 | 用户明确要求虚构人物对白 | 是否允许创作，人物声音是否有差别 |
| 其他赛道 | 用户自定义主题、文体和素材 | 是否尊重要求，避免强行套用已有形式 |

每个方向至少试一次默认选项，另选几篇填写可选目标、文体及材料；在相同模型、主题和素材下比较优化前后。记录模型及版本、时间、输入、原始输出、是否失败、用时和积分；用户修改后的稿件另存，不覆盖原始输出。

由编辑或获得授权的用户分别评价：标题是否兑现、内容是否有可用信息、事实是否有依据、结构是否匹配任务、是否存在重复或空话、需要修改多久、是否愿意发布。注明评价人和依据；没有真实反馈时标为待验证，不计算客户满意率，不把规则分数当作文章质量或外部检测结果。

出现事实编造、用户稿丢失、重复扣费、空选项导致无法生成等问题时先修复并复测；未能联系到用户或无法使用真实素材时，保留待验收状态，不编造试用结果。
