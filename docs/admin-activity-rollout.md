# 用户与活跃管理页面

入口：工作台账号菜单 → 用户与活跃；地址 `/admin/users`。

- 页面外壳公开，所有统计、邮箱、活动、任务与流水接口均执行 owner-only 权限校验。跨账号信号与重新聚焦清理旧数据后重新读取。
- 北京时间自然日，日期范围最多 91 天；默认普通用户，管理员可切换全部/管理员。普通用户不等于真实客户，暂不自动推断测试账号。
- 新增取 users.created_at；登录取成功登录/注册自动登录时明确写入的 users.last_login_at。不会把普通请求写成登录。
- 活跃从本次初始化开始记录：成功登录，或前台可见页面的可信键盘/鼠标操作；浏览器和数据库按分钟去重。后台轮询、系统执行、管理员代看不计入。没有历史访问证据的记录不回填。
- 单独页面及一键成文、书架共用轻量观察脚本；没有设备/IP/文章原文埋点。未完成全站细粒度行为追踪。
- 任务以 usage_records 为结算单元，jobs/workbench_jobs 按 usage_id 合并避免重复；无结算关联的独立队列任务另列。此数字为功能任务数，不是文章数或内部模型调用数。
- 失败任务与结算状态分别显示；执行失败不等于已退款。没有执行时间、扣分记录、重试来源时显示未知，不从候选状态推测。展示最近 50 条活动/流水，用户和任务列表分页 25。
- 增量表 user_activity_events、analytics_meta 用独立 SQLAlchemy metadata create_all(checkfirst) 初始化；不改现有钱包及认证表结构。回滚旧镜像可以保留两张增量表，不需要回滚业务数据。

验证：专项 API（权限、北京时间边界、去重、排除代看、失败状态）与 1440/390 浏览器交互；现有 Better Auth/登录浏览器回归。accounts_and_billing 基线 2fac95f 与候选均 19 passed / 4 failed（原有 SQLite 流水唯一性及 mock 接口问题），不将这些失败计为通过。

部署沿用官方脚本，requirements 未变时复用运行环境。上线后核对 readiness、静态文件哈希、匿名与普通账号权限、生产 PostgreSQL 聚合读取；不导出客户正文。
