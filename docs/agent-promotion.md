# 一级代理充值统计

代理由管理员以已注册邮箱开通；代理中心显示个人链接。新用户在同一浏览器通过链接注册时，注册请求携带独立推广码，仅首次注册绑定。停用只阻止新绑定，历史客户及其后续充值仍显示。旧邀请奖励不参与归属计算。

管理员页面按代理查询已入账充值订单、客户邮箱、订单金额、累计退款和支付时间。订单金额不一定是买家实付金额，页面不自动计算佣金或结算。非充值订单、未支付及尚未入账订单不显示。退款金额为订单当前累计值，不代表指定日期内退款额。

无需新增环境变量。新库按项目标准 `alembic upgrade head` 迁移。运行时必须在应用发布前创建代理表。对于历史线上库：部署时确认 Alembic 标记及实际表结构；如果旧标记落后且历史迁移已经由应用初始化建表，不应盲目运行完整升级。可使用 `python -m server.agent_schema` 在事务中只创建两张代理表，并保留原 Alembic 标记；该命令可重复执行，但不修复既有迁移漂移。未来标准迁移到 0014 时会检查表是否存在。

推广码保存在访问推广链接的浏览器中。若客户改用其他设备或清理浏览器存储后注册，无法自动归属。若写入归属失败，注册仍成功，界面会提示联系管理员；后台日志包含 agent signup attribution failed，需人工核对，不能假设归属已成功。不得从订单金额推断买家实付或返佣。

回滚应用不会删除两张新表，历史归属保留。不得降级或删除表来回滚数据。

代理中心的充值记录仅返回本人归属客户，客户邮箱脱敏。管理员可按北京时间付款日输入 0%–100% 的分成比例，系统按订单金额减所选订单当前累计退款计算预估，并以分为单位四舍五入。此结果不等于可自动结算金额：实际支付与订单金额可能不同，其他付款日的退款及结算后的退款需要人工处理，缺少付款时间的订单不会被计入日期。系统不记录转账或已结算状态，转账前必须核对历史记录，避免重复。
