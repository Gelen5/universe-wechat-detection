# 内容工厂 V3 定向审计

基线 `7515da767e0c5e5d45ada729568339b33d1add6a`，当前生产 release 为
`7ce3bc0`。本文件区分已验证实现、测试事实、真实付费结果和仍未验证的生产风险，
不能把测试替身通过当成真实模型联调或上线验收。

## 已实现

- **来源与选题**：新增 `server/content_factory_opportunities.py`。文章候选只读已有低粉榜快照；图片候选只有属于图文优先内容且匹配到低粉阅读基线时才标记为 `verified_lowfans_image`；热点只做精确标题匹配。历史选题库只作为灵感，原文链接、观测日期、阅读展示和局限说明随候选保存。
- **证据与状态机**：新增 `server/content_factory_v3_store.py` 及六张独立 V3 表。候选、标题、生产、质量、上架、异常和尝试次数均有持久化状态；Run 证据和商品详情可追溯。
- **标题与生成**：`server/content_factory_titles.py` 校验公众号与贴图号各自的标题合同；`server/content_factory_v3_tasks.py` 使用有界供应商调用。生产提示只提供来源标题与主题，不提供来源正文，避免模型假称已引用未获得的材料。
- **质量门禁**：`server/content_factory_gates.py` 和 `server/content_factory_quality.py` 对缺失、未知或冲突证据失败关闭。文章要求 1000 至 1200 非空白字符、来源/事实/版权/安全/标题/编辑/存储检查和朱雀人工占比至少 0.8；图片还要求技术解码、3:4 尺寸、文字排版、全布尔视觉复核及版权/水印/品牌/IP 检查。
- **朱雀**：`server/content_factory_detector.py` 归一化官方结果；成功、失败、不可用均有明确状态，`detections` 只保存内容哈希、结果和用量，不保存正文。检测不构成原创、版权安全或平台推荐保证。
- **图片**：`server/content_factory_image.py` 在 3:4 画布上排版中文；`server/content_factory_vision.py` 发起一次全字段视觉复核。模型返回缺字段或非布尔值时不通过。
- **预算与调度**：`server/content_factory_v3_store.py` 在派发前按上限预留，并检查完整流程预算。`server/content_factory_v3_tasks.py` 一次调用失败后不自动重试；`server/celery_app.py` 注册 V3 Worker 与 08:00/15:00 北京时间定时项。定时项在数据库开关关闭时无副作用。
- **自动上架**：`server/content_factory_v3_tasks.py:produce_draft` 在最后事务中将草稿、商品详情、质量报告、Run 状态和已上架状态串联保存。紧急停止、生产开关、上架开关、质量结论和内容指纹唯一约束共同控制；已有草稿人工重试会复用同一 `product_id`。
- **重试与异常**：尝试号会进入 Provider 幂等键。消息队列提交结果不确定时保留预留和排队状态，管理员可手动重派。超过标题 900 秒或生产 1800 秒的运行任务不会自动重新认领，只可由管理员标记异常，再显式人工重试。
- **后台与迁移**：`server/content_factory.py` 提供管理员设置、候选、指标、异常池、检测记录、派发、重试和人工上架控制。`20261107_0018` 和 `scripts/install_content_factory_v3_schema.py` 只增不删，并补齐已知的 `vision_call_bound_micros`、`attempt` 列。
- **调用明细**：新增 `content_factory_v3_provider_calls`，持久化标题、文章、图片和视觉调用的 token、图片数量与延迟；不写猜测价格。
- **候选排序**：已验证低粉图文优先于普通图文和非图文候选，避免小结果窗口把所有已验证来源截掉。
- **商品与钱包**：保留既有 `server/content_factory_purchase.py` 的独家买断、同事务扣分/账本/归属和原图授权访问；V3 不重复实现商城，也不改已有购买记录。

## 测试证据

已覆盖：

- 候选证据清洗、赛道和分数门槛；
- 标题合同和相似标题拒绝；
- 生成/质检调用次数有界，异常不会自动重试；
- Provider 幂等键包含 Run 与尝试号；
- 预算上限、完整流程预留、每日名额和人工重试不额外占名额；
- 文章自动上架、上架关闭时保留草稿、朱雀失败或重复执行不发布；
- 图片全布尔视觉门禁和私有图片访问；
- 紧急停止、管理员权限、指标与异常池统计；
- 消息队列重派及超时任务只进入人工异常；
- 缺列返回 503、V3 部分表结构可重复补齐。

已验证的测试组合见 `docs/CONTENT_FACTORY_V3_ACCEPTANCE.md`：当前完整相关套件为
`60 passed`，前端脚本语法和 `git diff --check` 均通过。真实生产调用和失败边界
也已记录在该验收文档中。

## 未验证与风险

- **没有 10 篇 + 10 图真实联调**：本轮完成 1 篇文章和 1 张图片的受控调用；文章被字数门禁拦截，图片供应商返回成功但交付阶段失败。
- **预算不是账单结算**：当前只按上限预留并保守占额，`settle_budget()` 尚未接入供应商账单。指标里的 `cost_micros` 不能被解释为已结算成本。
- **混合计价尚未落地**：文字、图片、朱雀和视觉调用的真实币种及换算口径尚未核对；视觉复核当前经过文字模型通道，不能按图片生成单价估算。必须统一到同一微单位口径后才能勾选费用已核实。
- **审计与原文核验仍不足**：系统只保存来源标题、榜单指标和链接；没有抓取来源正文，因此“事实与版权通过”是保守门禁结论，不是法律审查或人工已核验原文。
- **视觉复核不能保证**：图片文字完整性、人物/IP、版权、审美和平台合规无法仅靠模型保证；不确定时仍会暂缓，仍需人工抽检。
- **超时任务仍可能消耗费用**：人工标记异常只改变状态，不取消远端请求，也不证明旧任务失败。
- **迁移漂移**：生产 Alembic 历史标记与既有表结构不一致。正式迁移必须先备份和审计，不可直接假定 `alembic upgrade head` 安全。
- **生产并发未演练**：尚未在 PostgreSQL、Redis、多 Worker、Worker 强杀和 Beat 环境中验证竞争、恢复和部署行为。
- **生产已部署但交付未闭环**：生产 release `7ce3bc0` 已运行，基础设施和失败路径已验证；仍未得到一张通过全部门禁并保存为商品的 V3 图片。
- **管理员页面截图未完成**：本机 Chrome/代理路径阻塞浏览器自动化，生产页面和权限边界已通过 HTTP 与数据库核对。

## 发布边界

生产基础设施和受控失败路径已上线，但不能描述为“1 + 1 全部成功”或
“已经证明质量”。下一轮应先完成图片交付成功路径和真实管理员页面复核，再扩大到
10 + 10。不得自动重试已经产生图片费用的 Run，除非先确认幂等和账单。
