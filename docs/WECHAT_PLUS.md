# 公众号创作 Plus

用户明确要求：独立新增入口，现有公众号创作功能不修改。

交互目标：用户自然语言说明方向，按 Skill 缺失信息生成选题卡片、必要的风格/读者确认；已提供信息不能重复问。正文固定在右侧可编辑、可局部修改。允许已有正文直接改稿或排版。不是另套固定步骤表单。

架构约束：

- 独立路由 `/wechat-plus` 和账号隔离的持久会话。
- 以 weChat-autoCreate ArticleState 为文章状态源，调用原生 init/run/resume；不能仅加载说明书让模型冒充执行 Skill。
- 对话只处理请求和决定；正文、已选方向、证据、偏好、工具结果均落库。
- 后台任务与进度可恢复，刷新和断线后读取已有任务，不自动重复计费。
- 选项是结构化输入，可点击也可自然语言补充；重要决策由用户确认，重复机械确认去掉。
- 显式保存正文版本；编辑器更新有并发版本检查；新会话与旧会话可切换。
- 交付含正文、来源与限制、质量报告、排版预览；发布草稿需用户明确操作。
- 独立模型配置，首选实际供应商验证通过的 `claude-sonnet-5-5`，不修改全局模型或旧创作模型。

验收：新入口真实可见；真实模型走通选题→确认→必要偏好→成稿→改稿→排版；已有文稿直达；刷新恢复；账号隔离；取消/失败状态与积分可核；旧创作回归。不能用仅有前端、桩测试或接口200声称完成。

当前依据：2026-10-31已读取线上Skill主说明及ArticleState协议。供应商模型列表包含Sonnet5.5，但两次真实调用返回503；Sonnet5、4.6和GPT文本调用也失败。不能把模型列表当作可调用证明。Plus独立读取WECHAT_PLUS_TEXT_MODEL（默认gpt-6.1-sol），并支持独立API_BASE_URL/API_KEY；未配置时沿用文字供应商凭证。旧创作配置不变。

实现：独立wechat_plus模块、SQL会话/版本与任务记录、Celery chat队列。队列写入即outbox；60秒周期恢复未发布队列和过期租约；执行期间20秒续租。模型与检索结果按内容哈希缓存到任务，恢复可复用已完成调用。取消和最终保存原子互斥；正文乐观版本控制防止旧结果覆盖新修改。各任务使用独立交付目录。

界面：左侧对话与选题卡片，右侧正文/排版预览/复核来源。已有原稿直接走原生门禁和交付，不强制重新选题或研究。原生门禁阻塞时保存原稿和报告，不能伪造通过。内测入口暂不扣积分，沿用账号与分布式提交限流。
