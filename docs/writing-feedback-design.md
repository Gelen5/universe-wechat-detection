# 文章质量反馈与版本证据：待实施设计

目标是判断用户在哪里需要修改，而不是把规则命中率、模型分数或版本数当成满意度。此文件是实施设计；当前尚未增加采集、接口或数据留存。

## 现状和限制

- 公众号创作的作品版本有 `artifact.created` 和 `artifact.updated` 两种事件；版本来自模型、用户编辑或其他 API 时要按实际调用来源判断，历史缺失的事件不能重建。
- 一键成文以会话保存当前 HTML，保留有限的生成对话；新生成、排版、配图和手工保存均可能增加 revision，不能把 revision 增量当成用户改稿次数。
- 当前的一键成文去 AI 对照保存于草稿中，正文编辑后撤销会保护现有稿；重新生成成功后应清除旧对照，失败保留旧正文和对照。
- 现有保存数据并不证明用户同意用于人工评测。真实文章抽样必须先确认适当授权，再最小化使用、去除身份信息。

## 渐进实施建议

1. 先复用已存版本：公众号创作对有 `artifact.updated` 的作品检查来源与顺序；一键成文仅在当前会话内比较已有的生成内容与当前正文，明确可能包含排版、配图及程序修改，不能标记为纯人工编辑。
2. 设计用户主动提交的可选反馈，默认不提交；只问是否有帮助、最需要改进的地方与可选说明。写作、保存、复制与退出不依赖反馈。
3. 先决定是否真的需要存储正文或差异；默认优先使用不含原文的事件和汇总。若需要额外保存内容，实施前明确用户授权、访问范围、保留期限、撤回与删除流程，不能擅自从旧稿回填。
4. 若有足够的授权样本，用人工评审区分错误事实、素材不足、结构问题和语言问题；记录样本与条件，不以单个模型生成的评分替代用户判断。

## 验收与回滚

- 不反馈、不授权时，生成、保存、任务恢复、积分扣退和退出行为与原来一致；不增加模型调用或后台上传。
- 即使用户撤回或反馈服务失败，原有草稿仍可读、可编辑；跨账号不得读取他人反馈或对照内容。
- 所有新增记录须有清晰的删除和访问控制；取消该功能时关闭入口和采集，不删除既有稿件，也不重算积分。
- 真实手工修改次数、满意度和发布率，在事件及样本不足时标记为未知，不以版本数替代。
