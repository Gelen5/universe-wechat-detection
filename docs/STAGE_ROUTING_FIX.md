# 阶段路由修复：从"关键词猜"改成"模型理解"

日期：2026-10-23　基线：`ba0507f`
起因：P0 版本里 `resolveStage()` 用关键词猜阶段，输入「我准备写一篇关于AI相关的文章 给我下选题」时命中"写一篇"→ 直接跳到 **03 写作**，而用户要的是选题。

---

## 1. 根因

`static/conversation-workbench.js` 里两条规则的顺序决定了一切：

```js
[/正文|写一?篇|开始写|写作|续写|成稿/i, 'writing', hasOutline],  // 先命中
[/选题|方向|标题|热点|写什么/i, 'topic', true],                    // 永远轮不到
```

只要页面上已经有大纲，"写一篇"就会压过"选题"。**这是设计错误，不是规则没写全**：输入框不该有决定阶段的权力。

---

## 2. 新契约

| 谁 | 决定什么 |
| --- | --- |
| **标签页 / 继续按钮** | 用户显式指定阶段：`content_json.stage_explicit = true`，不调模型、不做判断 |
| **输入框** | 只发原话 + 当前标签作为**提示**（`workflow_stage`），阶段由模型判断 |
| **后端** | 一次结构化调用（`server/agent/intent.py`）返回要执行的阶段 |
| **失败时** | 任何异常/超时/JSON 不合法 → 回到当前标签，绝不因此让 run 失败 |

### 模型返回什么

```json
{"stage":"topic|outline|writing|deai|typeset|null",
 "direction":"…","selected_topic":"…","instruction":"…",
 "reason":"给用户看的一句说明","confidence":0.0-1.0}
```

- `stage = null` = 这句话是提问，不是要执行阶段 → 直接回答，**不调工具、不产出作品**。
- **换阶段或回答提问需要 `confidence ≥ 0.55`**；继续当前阶段不需要（避免"不太确定"把用户卡住）。
- 判断依据：当前标签、已有产物类型、正文标题、最近 6 个选题、最近 6 条对话、用户原话。提示词里明确写了"不要按字面关键词，例如'写一篇…给我下选题'是 topic"。

### 用户看到什么

- 模型换了阶段 → 标签自动切过去，对话里留一条灰底说明「已理解：先给你 10 个选题」，并且**落库**（刷新后仍在）。
- 模型认为是提问 → 直接回答，不产生作品。
- 模型不确定 → 按当前标签执行，不跳来跳去。

## 3. 你确认的四条，逐条落地

| 你的决定 | 实现 |
| --- | --- |
| 手动点击推进 | 一步完成后不自动进入下一步；「继续：X」按钮才是推力 |
| 不要关键词、要模型理解 | 删掉 `resolveStage()` 与全部正则；阶段由 `intent.py` 判断，提示词禁止按字面猜 |
| 允许越级执行 | 不再拦截"没大纲就写正文"；缺前置时照常执行，失败会有清楚的失败卡片 |
| 一起修上下文过长 | `context.py` 按阶段裁剪，见下 |

---

## 4. 上下文按阶段裁剪（顺手修掉"写作"的模型报错）

旧的 `conversation_messages()`：最近 **40 条**消息 + 最多 **60000 字**的全部作品 + 整份 SKILL.md + 阶段指令。写作那一步因此容易顶到模型上限，报「模型服务返回了错误」。

新的 `stage_messages()`：

| 阶段 | 带给模型的 |
| --- | --- |
| 选题 | 不带任何作品正文，只有作品索引 + 最近 12 条对话 |
| 大纲 | 选题清单（≤4000 字） |
| 写作 | 大纲（≤6000 字），**不再带整篇正文和 HTML** |
| 去 AI | 正文摘要（≤2000 字），工具自己会读全文 |
| 排版 | 正文摘要（≤2000 字） |

单条消息截断 800 字，最近 12 条。实测写作阶段提示词从 6 万+字降到几千字。

## 5. 数据与兼容

- 新增 `runs.stage`（可空）+ 迁移 `db/alembic/versions/20261023_0008_run_stage.py`。失败卡片、重试、统计都以它为准，不再从触发消息里反推。
- **非工作台入口保持原样**：没有 `workflow_stage` 的消息（自动对话、其它调用方、既有测试）仍然是"全部工具可用、无强制阶段"，不会被新的回答模式影响。
- `run.failed` / `runs` 视图依旧只暴露 `error_code`，不泄漏 provider 原文。

## 7. 上线注意

1. web + worker 都要重启；
2. **执行迁移**：`alembic upgrade head`（新增 `runs.stage`）；
3. 静态资源版本 `?v=20261023-routing`；
4. 每条输入框消息多一次轻量模型调用（约 300–600 tokens 输入、≤150 tokens 输出，25 秒超时），失败自动降级；按钮/标签点击不产生这次调用。
